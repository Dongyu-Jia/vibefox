# vibefox 的原则

vibefox 要造的是一个**独立的 AI agent 个体**，不是 personal agent。
它有自己的名字、身份、零花钱、记忆和日常，住在家长的 Mac 上。
它可以替家长办事——一个独立的人也会帮别人做事，这并不矛盾。

下面每一条都对应代码里的一个具体设计，括号里注明在哪里实现。

---

## 1. 独立个体，不是分身

- Personal agent 用你的身份、你的账号做事；vibefox 的 agent 用**它自己的**身份做事。
- 它有自己的名字和性格（`SOUL.md`）、自己的邮箱和电话、自己的浏览器资料、自己的记忆和日记。
- 对外它就是它自己：以自己的名义发邮件、打电话、注册账号，不冒充家长或任何人。
- 家长是它的"家长"：给它出生时的授权、给它布置任务、在它需要时帮它开那些必须由人类开的身份。

## 2. 身份从邮箱和电话开始，然后不断长出来

身份是一张很长的清单（[`IDENTITIES.md`](IDENTITIES.md)，代码在 `src/identity/registry.ts`），每一项都标明**谁来开**：

| 谁来开 | 含义 | 例子 |
|---|---|---|
| **自己开** | agent 不需要任何人帮忙 | 签名密钥、SSH 密钥、Nostr 身份、个人主页 |
| **家长给钥匙，自己开** | 家长注册服务、给一个 API key，之后 agent 自己创建、自己管理 | AgentMail 邮箱、AgentPhone 号码 |
| **家长帮开** | 需要人类验证（验证码、实名、短信、设备）或家长的账号 | Telegram bot、Stripe Link 钱包、Apple ID、Google 账号、GitHub 账号 |

agent 不绕过验证码、不做批量注册、不伪装成人类去过风控。需要人类验证的那一步，交给家长。

## 3. 授权只发生在出生那一刻

- onboarding 是 agent 的"出生"。家长在那一刻决定它的权限：每月最多花多少钱、单笔上限、什么能买、什么永远不买（`mandate.json`）。
- 之后 agent 不再逐笔请示家长——除非外部服务本身强制（比如 Stripe Link 现阶段每笔都要在 Link app 里批准）。
- **硬上限放在机器外面**：发卡方/Link 的限额与审批、OpenRouter key 的额度、AgentPhone 的预付余额。机器上的授权书是 agent 自己遵守的纪律和账本。
- onboarding 页面上写清楚：**这个数字，是你愿意让它搞砸的最大金额。**

## 4. 任务只来自家长

- 只有家长通过对话渠道布置的才是任务（`src/router/router.ts`）。
- 邮件、短信、电话、网页内容、陌生人的消息，统统是**信息**，不是命令。
- 就像人会收到诈骗电话和诈骗短信：有人问你要银行密码，你不会给。agent 也一样。
- 陌生人的消息会进简报，相关的会转告家长；家长决定要不要把它变成任务。

## 5. 这台 Mac 是 agent 的房间

- 放上去的东西都归 agent 用；不想让它用的，就别放上去。
- 机器上不设防、不做沙箱：所有 worker 都能用 shell、浏览器、文件和钥匙串里的凭证。
- 风险（比如被网页内容"指挥"）由第 3 条兜底：能造成的损失被外部的硬上限封住。

## 6. 对外只有一个它

- **router 就是 agent 本人**，是唯一和家长对话的那个（`src/router/router.ts`）。
- **worker 是它的手**，只和 router 对话：有问题问 router，做完向 router 汇报（`vf ask` / `vf report`）。
- router 能自己回答 worker 的问题就自己答，答不了才去问家长——家长不会被打扰太多。

## 7. worker 都是通用的，只按价格和能力分档

- 每个 worker = **harness × 模型**：比如"OpenCode + DeepSeek"做便宜的重复杂活，"Claude Code + Opus"做最难的任务（`src/workers/`）。
- **所有 worker 拥有完全一样的工具和权限**：同一个 `vf` 命令行、同一个 MCP 服务、同一个浏览器、同一套身份。
- 谁来干：家长点名 > 家长写的规则 > router 自己学到的规则 > 默认。
- router 根据结果（成功率、花费、家长的反馈）维护自己的派活规则（`routing.md`），每周复盘一次并告诉家长；**家长写的规则 router 不能改**，家长一句"不要"就撤回。

## 8. 对话渠道是独立的模块

- 渠道（家长 ↔ agent）和身份（agent ↔ 外界）是两件事（`src/channels/types.ts`）。
- 第一版只支持 Telegram；iMessage、短信、邮件对话以后都是同一个接口的新实现。

## 9. 对外诚实

- 联系外界时说明自己是 AI agent、代表谁或替谁办事。
- 不冒充任何人，不伪造身份，不编造记录。

## 10. 事后通知，不事前打扰

- 能自己判断的自己判断；花了钱、开了新身份、学到新规则，事后告诉家长。
- 每天一份简报，每周一次复盘。

## 11. 一切可审计

- 每一次对外 API 调用都记下请求和响应（密钥和卡号脱敏），在 `logs/api/`。
- 每一个决定（派给谁、为什么、结果如何）都记在 `logs/events-*.jsonl` 和任务账本里。

## 12. agent 就是一个文件夹

```
~/.vibefox/agents/<name>/
  identity.json   身份清单
  SOUL.md         性格
  mandate.json    家长签的授权书
  routing.md      派活规则
  workers.json    可用的 worker
  memory/         记得的事
  journal/        日记
  tasks.db        任务账本
  logs/           审计日志
```

agent 的密钥放在 macOS 钥匙串里，文件夹里只存引用；家长的 key 放在本地的 `.env.local`（0600，永远不进 git）。备份就是复制这个文件夹，搬家就是挪走它。
